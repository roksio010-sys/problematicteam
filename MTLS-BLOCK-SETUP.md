# Блокировка устройства через Cloudflare mTLS

Эта версия добавляет привязку к клиентскому сертификату Cloudflare. В отличие от Visitor ID, IP и cookies, сертификат проверяется Cloudflare на TLS-уровне.

## Что сделать

1. Выполнить `schema-mtls-device-block.sql` в той же D1-базе, которую использует `cloudflare-worker.js`.
2. Задеплоить обновлённый `cloudflare-worker.js` в существующий Worker журнала.
3. Создать отдельный Cloudflare Worker из `cloudflare-edge-worker.js`.
4. Для нового Edge Worker задать переменные:
   - `ANALYTICS_WORKER_URL` = `https://pmt-visitor-log.roksio010.workers.dev`
   - `EDGE_SHARED_SECRET` = длинная случайная строка. Точно такую же строку добавить в существующий Worker журнала как Secret.
   - `REQUIRE_CLIENT_CERT` = `false` для обычного режима; `true`, если доступ к сайту должен быть только у устройств с клиентским сертификатом.
5. В Cloudflare включить mTLS для hostname твоего домена: **SSL/TLS → Client Certificates → Hosts → Edit**. Cloudflare указывает, что mTLS можно включить для любого hostname; затем клиентские сертификаты устанавливаются на разрешённые устройства.
6. Создать Worker Route:
   `твой-домен/*`
   и направить её на новый Edge Worker.
7. DNS-запись домена должна быть **Proxied** (оранжевая тучка), иначе Worker Route не будет находиться перед GitHub Pages.
8. Выпустить отдельный клиентский сертификат для устройства, которое нужно идентифицировать. При посещении с ним в журнале появится `mTLS Serial`.
9. В журнале нажать **«Заблокировать сертификат»**.

## Важное ограничение

Режим `REQUIRE_CLIENT_CERT=false` позволяет обычным посетителям без сертификата заходить на сайт. Поэтому пользователь заблокированного устройства, если у него нет обязательного mTLS, теоретически может удалить/не предъявлять сертификат.

Если требуется режим, в котором **вообще каждый вход на домен обязан иметь клиентский сертификат**, установите `REQUIRE_CLIENT_CERT=true`. Тогда смена браузера/IP без действительного сертификата не даст доступа. Все разрешённые устройства должны заранее получить свои сертификаты.

mTLS не является абсолютным «серийным номером железа»: экспортируемый клиентский сертификат можно перенести на другое устройство. Для максимально сильной привязки ключ сертификата следует хранить в защищённом аппаратном хранилище/TPM и не делать его экспортируемым.
